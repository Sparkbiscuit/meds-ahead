## 1. Before the 1.1 archive, if the time is there

### 1a. The scanner's pills wrap into the frame

With "Exact match" in the Name pill, the pill row wraps to a second line that
overlaps the green frame. `ScanFrameLayout.topInset` is a constant sized for the
old row. Fix in two parts: keep the pill title "Name" and change only the symbol
to `checkmark.seal.fill` for the exact-match state, with an accessibility label
of "Name, exact match" (the guidance banner already says it in words); and make
the frame honest by measuring the pill flow's height with `onGeometryChange` and
driving the top inset from it, for both the drawn outline and
`DataScannerViewController.regionOfInterest`, which must stay one source of
truth. Check at the largest accessibility text size, where the row wraps even
without the exact-match state.

### 1b. NDC read reliability on real bottles

Two real bottles failed to yield their NDC live on September 12, even zoomed in,
on a build from that afternoon's final commit. **Nick then checked the review
screen's Scan evidence and found no line containing the code at all**, so
recognition never produced it and the parser is not the first suspect. The
rendered-label tests read a code at one percent of the frame through the still
pipeline, so the gap is between VisionKit's live recognition, the Review
capture, and the digits pharmacies actually print. Debug builds now show a
capture note at the top of Scan evidence: the photo's pixel size, the crop
taken from it, the zoom, how many lines and codes the capture read, and the
evidence counts before and after the merge cap. Read that line on both bottles
before touching anything. It decides between these:

- **The capture never ran.** `captureCroppedPhoto` throws (`invalidCapture` from
  the crop mapping, or `capturePhoto` itself) and the error is swallowed when
  live evidence exists. The note reads "Review capture failed".
- **The capture is too small.** If `capturePhoto()` returns a preview-sized
  frame rather than a sensor-sized photo, a 2 mm line is ten pixels tall and
  unreadable. The note's pixel size answers this; the fix is a still capture
  through the session's own `AVCapturePhotoOutput`, or reading the largest
  frame VisionKit will give.
- **Zoom is ignored.** `AspectFillCropMapper` assumes an unzoomed, aspect-filled
  preview. Pinched to 3×, the crop still maps the frame onto the unzoomed image,
  so the line the person centred is a small region of a small region. The note
  prints the zoom; the fix scales the crop by `zoomFactor` about the centre, or
  skips cropping when zoomed.
- **The merge cap cuts the capture.** `ScanEvidenceQuality.evidenceLimit` is 80
  and additions land after what is held, so on a text-heavy label the capture's
  lines are the ones cut. The note prints the counts either side of the cap.
  Raise the cap, or merge the capture ahead of live items.
- **Live items never stabilise at zoom.** The live tracker promotes an item only
  after 0.4 s with a stable identity; at high zoom a hand tremor churns
  identities, so nothing from the live pass survives. The capture pass is the
  answer to this one, which is why the first three matter most.

Then, whichever it is, fix in this order:

- **Gather.** Take a photo of each label and run it through Choose Photo, which
  uses the still pipeline at full resolution: if the code appears there, the
  camera path is the whole problem. Copy the recognized lines (patient name
  removed, nothing committed) into a new case in `PrescriptionLabelEndToEndTests`.
- **Repair every digit confusable after the caption.** Today only O, I and l are
  repaired. After "NDC" no letter is possible, so map B→8, S→5, D→0, Z→2, G→6,
  Q→0, T→7 as well, and accept spaces where hyphens should be
  ("NDC 00093 1039 01") when the segment widths fit a native layout.
- **Join adjacent lines before matching.** A code split at a hyphen across two
  recognized lines ("NDC 00093-" / "1039-01") matches nothing today. The parser
  already knows capture adjacency; match on line plus next line too.
- **A zoomed second pass on the Review capture.** For any recognized line
  containing "NDC" or a partial code shape, crop that line's bounding box with
  padding from the full-resolution capture, upscale it three times, and run
  `VNRecognizeTextRequest` again with `usesLanguageCorrection = false`. Language
  correction is built for words, and a code is not a word.
- **Manual NDC entry on the review screen.** A field under the product-code row:
  type the code off the bottle and the directory fills name, brand, strength and
  form through the same gate. Exactness should never depend on OCR alone.
- **Distinguish "not read" from "read but refused".** If the code was read and
  resolved but the label failed corroboration, the review screen should say so
  ("Code read as 00093-1039-01 names sertraline; the label says otherwise")
  rather than silently showing nothing.

Acceptance: both bottles from September 12 resolve exactly on the phone, live or
on Review, and the new regression cases pass.

### 1c. Text-heavy labels defeat name detection, and directions rarely fill

A label with long directions (several wrapped lines, doses restated in
parentheses, "as needed for …") produced no name, and the directions field is
empty on most real labels. The name failure is the serious one. Hypotheses, to
confirm against the gathered lines:

- `capturedStrength` takes the first non-direction line carrying a strength. A
  sig fragment that does not open with a verb ("(25 MG) BY MOUTH EVERY 6 HOURS")
  is not direction-like by the current test, so it becomes the strength line,
  the name search runs on it, finds nothing plausible, and the product line is
  never consulted.
- `isTrustedDirections` demands a verb or dose phrase at the start, a frequency,
  no dispensing words and at most three joined lines. Real sigs wrap over four
  or five lines and open mid-sentence after a wrap.

Plan: prefer, as the product line, the strength-bearing line that also carries a
vocabulary-known token or a name-shaped run; treat lines containing sig
vocabulary anywhere ("every", "hours", "as needed", "for", "with food",
parenthesised doses) as directions for the purpose of choosing the strength
line; assemble wrapped sigs from up to five adjacent lines in one capture, and
accept the joined text through the same trusted gate. Exact identification
sidesteps the name problem entirely, which is why 1b comes first.

## 2. Health dose sync

Doses logged in Health after a medication exists here should charge its
supply; today only the pre-count history is imported, with the supply flag off.

- **Identity.** Sync medications that carry a Health identity: imported ones
  match by RxNorm code (`productIdentifier` of type RxNorm). With the RxNorm
  table below, scanned bottles gain a code too. Never match by name for anything
  that changes supply.
- **When.** On launch and on returning to the foreground, beside notification
  replanning. HealthKit background delivery later, if ever.
- **Query.** `HKUserAnnotatedMedicationQueryDescriptor` for the shared
  medications (no picker; the picker is only for the import screen), then
  `HKSampleQueryDescriptor` on `medicationDoseEventType()` per concept since the
  last sync, taken and skipped statuses. Never request the dose-event type with
  `requestAuthorization(toShare:read:)`; HealthKit throws an uncatchable
  exception. The per-object medication grant covers dose events.
- **Never twice.** `DoseEvent` gains `healthSampleID: UUID?` (inline default,
  lightweight migration, verified with the worktree recipe in the release
  workflow). A Health sample already stored is skipped; a sample that has gone
  from Health (undo) removes its copy.
- **Never double.** A Health dose with a scheduled date maps to the app's slot
  through `ScheduleEngine`; if that slot is already logged here, skip. An
  as-needed Health dose within thirty minutes of an app-logged dose for the same
  medication is the same dose; skip. Skipped in Health becomes skipped here.
- **Still read-only.** Logging here does not mark Health. Say so in the Apple
  Health screen's copy.
- Tests: the dedupe rules as pure functions over plain values; a migration
  check; a hands-on pass in the simulator's Health app, where logging a dose is
  Medications page > Log row > Taken > Done.

## 3. RxNorm table

Source: NLM's RxNorm monthly release; the "current prescribable content" subset
needs no UMLS license. Trim to an NDC → RXCUI table plus each RXCUI's
prescribable name, bundled like the FDA snapshot, with NLM's attribution (the
Safety sheet already carries it). Uses, in order of value: link a scanned bottle
to its Health medication for the sync; recognise every generic maker of the
same drug, strength and form as one medication; shorten FDA names generally
through the prescribable names; print the code clinic systems use on the shared
list. A few megabytes; a second build tool beside `build_ndc_directory.py`.

## 4. Features

Batch the stored-property additions below into one `@Model` change and verify
the migration once.

- **Pharmacy card.** Store pharmacy name and phone (the label prints both; the
  parser can capture them) and the Rx number the pharmacy barcode already
  carries. On the detail screen: "Call pharmacy" with the Rx number shown large
  enough to read aloud, and "Refill by phone" as the low-supply alert's action.
- **Refill in progress.** A state with a date: requested, or ready for pickup.
  The forecast stops alarming, Today says "pick up Friday", and the refill
  sheet is prefilled when it arrives.
- **Widgets.** Home and Lock Screen: next dose, and "runs out next". A new
  widget target sharing the store through an app group; App Intents come with
  it. The largest item here.
- **Trip check.** In Supply, pick a return date and see which medications need
  a refill before leaving. Pure forecast arithmetic.
- **Who it's for.** A person tag per medication; Today, Supply and the shared
  list grouped by person. A step toward the 1.3 caregiver sharing.
- **Expiration reminders.** Expiration dates are captured; a week ahead, notify,
  through the global planner with the same cap.
- **Adherence calendar.** A month view of taken and skipped per medication, and
  "doses logged in the last 30 days" on the shared list.
